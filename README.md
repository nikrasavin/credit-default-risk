# Credit Default Risk

Предсказание серьёзной просрочки по кредиту на данных соревнования
[Give Me Some Credit](https://www.kaggle.com/c/GiveMeSomeCredit) — 150 000 заявок, 10 признаков.

Проект отвечает не на вопрос «какую метрику удалось выжать», а на вопрос
**«при каком пороге одобрения банк зарабатывает больше всего»**.

## Результат

- **ROC-AUC 0,869** на отложенной выборке, которая не использовалась ни для одного решения в проекте
- Отказ 10,8% самых рискованных заявок повышает прибыль портфеля на **20,3%**
  относительно политики «одобряем всех»
- Оптимальный порог 0,164 совпал с теоретическим 1/6, что подтверждает
  корректность вероятностей модели
- Главный источник качества — не модель, а разведка данных: обнаруженные
  служебные коды в счётчиках просрочек дали линейной модели +0,12 ROC-AUC

## Ключевые находки в данных

Метод проверки везде один: сравнить долю дефолтов в аномальной группе с базовой (6,68%).
Аномалия, связанная с таргетом, — это сигнал, а не мусор.

| Находка                                                              | Масштаб           | Дефолт в группе  | Решение                                                  |
| -------------------------------------------------------------------- | ----------------- | ---------------- | -------------------------------------------------------- |
| Значения 96 и 98 в счётчиках просрочек — служебные коды, а не данные | 269 строк (0,18%) | **54,7%**        | заменены на `NaN` + бинарный флаг                        |
| `RevolvingUtilization` > 1 при смысле «доля лимита»                  | 3 338 (2,2%)      | **37,2%**        | оставлены как есть; клиппинг только для линейных моделей |
| Пропуски в `MonthlyIncome`                                           | 29 731 (19,8%)    | 5,6% против 6,9% | флаг `income_missing` + медиана внутри Pipeline          |
| `DebtRatio` у строк без дохода содержит сумму, а не отношение        | те же 19,8%       | —                | покрывается флагом `income_missing`                      |
| Пропуски в `NumberOfDependents`                                      | 3 924 (2,6%)      | —                | заполнены нулём                                          |
| `age` = 0                                                            | 1 строка          | —                | отмечена в ограничениях                                  |

Клиенты без указанного дохода старше остальных (медиана возраста 57 против 51)
и **реже** уходят в дефолт. Вероятно, это пенсионеры: доход невелик, но стабилен.
Пропуск здесь — не дырка в данных, а признак.

## Сравнение моделей

Валидация: стратифицированная 5-фолдовая кросс-валидация на 120 000 строк.
Отложенные 30 000 строк открыты один раз, в самом конце.

| Модель                  | Сырые признаки  | С обработкой аномалий | Вклад обработки |
| ----------------------- | --------------- | --------------------- | --------------- |
| Логистическая регрессия | 0,6936 ± 0,0096 | 0,8133 ± 0,0034       | **+0,120**      |
| Градиентный бустинг     | 0,8630 ± 0,0028 | 0,8636 ± 0,0024       | +0,0006         |

**Обработка выбросов критична для линейных моделей и почти безразлична для деревьев.**
Логистическая регрессия умножает признак на вес, и 269 строк со значением 98
в счётчике с нормальным диапазоном 0–17 придавливали коэффициенты трёх сильнейших
предикторов. Дерево режет по порядку значений, и для него такая строка —
просто «правее порога».

### Абляция: что именно дало прирост линейной модели

| Конфигурация                | ROC-AUC |
| --------------------------- | ------- |
| Без обработки               | 0,6936  |
| Только флаги аномалий       | 0,8125  |
| Только маскирование кодов   | 0,8078  |
| Флаги и маскирование вместе | 0,8133  |

Два приёма по отдельности дают почти весь прирост, а вместе — почти ничего сверх него.
Значит, они не дополняют друг друга, а лечат одну и ту же проблему разными путями.

## Экономика решения

Модель выдаёт вероятность; банку нужно решение. Порог выбирается не по F1,
а по соотношению цены ошибок: одобренный хороший клиент приносит `+1`,
одобренный плохой — `−5`, отказ даёт ноль.

Оптимальный порог при таком соотношении: `p* = GAIN / (GAIN + |LOSS|)` = **1/6 ≈ 0,167**.
Эмпирический оптимум по out-of-fold предсказаниям — **0,164**.

Кривая прибыли около максимума пологая: пороги от 0,12 до 0,22 практически
эквивалентны. Бизнесу правильнее сообщать диапазон, а не одну точку.

### Устойчивость к предположениям

Сумма кредита в данных отсутствует, поэтому расчёт ведётся в условных единицах
на клиента. Проверка при разных соотношениях цены ошибок:

| Убыток на дефолте | Оптимальный порог | Теория | Одобрено |
| ----------------- | ----------------- | ------ | -------- |
| −2                | 0,327             | 0,333  | 94,9%    |
| −3                | 0,243             | 0,250  | 92,6%    |
| −5                | 0,164             | 0,167  | 89,4%    |
| −8                | 0,109             | 0,111  | 84,7%    |
| −12               | 0,074             | 0,077  | 78,0%    |

Эмпирический оптимум совпадает с теоретическим во всех сценариях — вероятности
модели корректны независимо от экономических допущений. Чем дороже дефолт,
тем строже отбор; модель при этом одна и та же, меняется только цена ошибки.

Калибровка проверена отдельно: точки кривой надёжности лежат на диагонали
вплоть до риска 37%. Коррекция не потребовалась.

## Что модель использует

Permutation importance, измеренная на 30 000 строк, не участвовавших в обучении:

| Признак                                  | Падение ROC-AUC при перемешивании |
| ---------------------------------------- | --------------------------------- |
| `RevolvingUtilizationOfUnsecuredLines`   | 0,0783                            |
| `NumberOfTimes90DaysLate`                | 0,0351                            |
| `NumberOfTime30-59DaysPastDueNotWorse`   | 0,0339                            |
| `NumberOfTime60-89DaysPastDueNotWorse`   | 0,0161                            |
| `age`                                    | 0,0110                            |
| доход, долговая нагрузка, число кредитов | ≤ 0,006                           |
| `NumberOfDependents`                     | 0,0002                            |

**Кредитное поведение даёт около 84% всей важности; анкетные данные почти не работают.**
Для банка это означает, что подключение кредитного бюро ценнее любого усложнения анкеты.

SHAP расставляет признаки иначе: производный `late_total` забирает вклад трёх
исходных счётчиков, потому что несёт ту же информацию. Ни один метод не даёт
«истинной важности» при коррелированных признаках — смотреть нужно на оба
и понимать, что каждый измеряет.

## Объяснение отдельного решения

Для каждой заявки SHAP раскладывает предсказание на вклады признаков; сумма
вкладов в точности воспроизводит оценку модели. Пример пограничного клиента
(итоговая вероятность дефолта 16,4%):

> Решение по заявке отрицательное. Основная причина — три просрочки платежей
> на срок 30–59 дней за последние два года. Дополнительно учтено, что использовано
> 63% доступного кредитного лимита и открыто 17 кредитных линий. В пользу заявителя
> учтены возраст и отсутствие просрочек свыше 90 дней, но этого недостаточно
> для одобрения.

Такое объяснение — основа adverse action notice, уведомления об отказе,
которое кредитор обязан выдавать заёмщику в ряде юрисдикций.

## Ограничения

- В данных нет суммы кредита и срока, поэтому экономика считается в условных
  единицах на клиента. Абсолютные суммы прибыли не имеют смысла, относительные — имеют.
- Данные статичны и относятся к одному периоду. Поведение заёмщиков меняется,
  и модель требует регулярной перепроверки на свежих когортах.
- `age` работает как предиктор, но использование возраста в кредитном скоринге
  ограничено регуляторно во многих юрисдикциях. Перед внедрением нужна проверка
  модели на смещение по защищённым группам.
- Одна запись с нулевым возрастом оставлена в данных: на 150 000 строк влияния нет.
- Порог выбран по усреднённой экономике. Реальный банк считает её по сегментам
  продукта, и оптимум в каждом будет свой.
